make([]T, len, cap) // то же, что и make([]T, cap)[:len]

Функция-значение - это когда присваиваешь обычную именованную функцию переменнойю

Интерфейс является абстрактным типом

Это может казаться бесполезным, но на самом деле тип interface{}, который называется Пустым Интерфейсом, является необходимым. Поскольку тип пустого интерфейса не накладывает никаких требований на типы, которые ему соответствуют, пустому интерфейсу можно присвоить любое значение.

Вызов любого метода нулевого интерфейса приводит к аварийной ситуации.

Сравнивайте значения интерейсов, только если уверены, что они содержат динамические значения сравниваемых типов.

Интерфейс, содержащий нулевой указатель, не является нулевым! Нулевое значение интерфейса, которое не содержит значения как такового, не совпадает со значением интерфейса, содержащим нулевой указатель.

статические ошибки, т.е. на ошибки, которые можно обнаружить без запуска
программы
Отделяя статические проверки от динамических, можно быстрее обнаруживать ошибки и выполнять много проверок только один раз, вместо того чтобы
выполнять проверки при каждом вычислении выражения.

При проектировании инерфейса стоит следовать праввилу "запрашивайте только самое необходимое".

Go обеспеивает два стиля параллельного программирования - 
1 го-подпрограммы(goroutines) и каналы, которые поддерживают взаимодействующие последовательные процессы (communicating sequential processes - CSP), модель параллелизма, в которой между независимыми процессами(go-подпрограммами) передаются значения, но перемененные по большей части ограничиваются одним процессом.
2 многопоточность с общей памятью.

Горутина - каждая одновременно выполняющаяся задача.

Главная горутина - та, которая вызывает функцию main.

новые горутины создаются с помощью инструкции go.

Аргументы функции, запускаемой с помощью go, вычисляются при выполнении самой инструкции go.

Канал представляет собой механизм связи, который позволяет одной go-подпрограмме отправлять некоторые значения другой go-подпрограмме.

Канал имеет две операции, отправление и получение, вместе известные как коммуникации.

Операция отправления в небуферизованный канал блокирует go-подпрограмму до тех пор, пока другая go-подпрограмма не выполнит соответствующее получение из того же канала, после чего значение становится переданным, и обе go-подпрограммы продолжаются.

Попытка закрыть уже закрытый канал вызвывает аварийную ситуацию, так же как и закрытие нулевого канала.

Когда канал используется в качетсвет параметра функции, это почти всегда делается с тем намерением, что он должен использоваться исключительно для отправления или исключительно для получения данных.

chan<- int - канал только для отправления
<-chan int - канал только для получения

Ошеломляюще параллельные задачи - задачи, котоые состоят исключительно из полностью независимых одна от другой подзадач.

Две операции - ожидание счетчика и закрытия канала, должны выполняться параллельно с циклом, работающим с каналом.

Подсчитываемый семафор - примитив параллелизма, буферизированнй канал с емкостью n
 
Хорошая практика заключается в том, чтобы операции с семафорами располагались как можно ближе к операциям ввода-вывода, которые они регулируют.
